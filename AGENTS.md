# mgu-ui-builder

## Agent skills

### Issue tracker

Issues and specs live as local markdown files under `.scratch/<feature>/`. See `docs/agents/issue-tracker.md`.

### Triage labels

Default five-role vocabulary (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), recorded as a `Status:` line in each issue file. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.

## Layout and tooling

- `kit/`: the vendored kit, a pinned unmodified copy of mgu-store's (`SOURCE.json` records the commit and each file's blob id). Never edit it; change the kit in mgu-store, then `npm run sync-kit -- --from <mgu-store clone> --commit <rev>`.
- `runtime/`: the runtime (Node 8, CommonJS; modules require each other and the kit by basename, `./x.js`, as the OAP linker lays an app out flat). `mgu_runtime.js` is the platform-free core (screen file in, recordings out to a sink, input in; it follows `nav` links and keeps the screen stack for BACK); `mgu_focus.js` holds focus order, actions, hit testing and the focus ring; `mgu_keyboard.js` is the keyboard screen a field opens (the core keeps it as an overlay over the shown screen, so BACK there cancels before any screen stack sees it); `mgu_headunit.js` adapts it to the render client and the HMI's page (RHMI states per depth: shown while the HMI shows one, BACK, proxies, FrontCCU, display language, keepalive); `mgu_oap.js` is the OnlineApp around it (it takes the oap-sdk modules from the app's entry, so nothing else requires them) and names the page states `starter/tools/gen_package.js` writes. `mgu_pictures.js` hands the kit the PNGs a screen file names by path (`images/x.png`) as data URLs; the bytes come from `readImage` (fs on the head unit, the open design in the preview). `designer/`: the Designer (React + Vite + TypeScript, an npm workspace: run `npm install` at the root). `npm run designer` starts the dev server, `npm run build-designer` type-checks and writes the static build to `designer/dist/`. Its preview runs the runtime and the kit unchanged in the browser through the `virtual:mgu-runtime` module (`designer/vite.config.ts`: esbuild bundles them flat, `zlib` and `Buffer` shimmed in `designer/src/shims/`). The Designer's document model is `designer/src/model/` (TypeScript, no React; Node runs it directly in the tests): every edit is an operation applied by `apply(doc, op)` (undo/redo in `history.ts`); each group of operations is a module under `model/ops/` exporting handlers, merged in `model/operations.ts`, so a new group is a new module plus one line there. `designer/src/catalog.ts` is the hand-written widget catalog (kept equal to the kit by `test/widget-catalog.test.js`). Model files import each other with `.ts` extensions. The UI (see ADR 0002): editor state is one Zustand store, `designer/src/store/editor.ts` (plain TypeScript over `zustand/vanilla`, so Node tests it; `store/react.tsx` is the provider and `useEditor(selector)`/`useActions()`). Components read the store and edit through its `edit(op)` (a refusal sets `problem`), never through props from `App`. Layout like Figma's UI3: `shell/` holds the toolbar (main, insert and View menus, Try, zoom), the panel frame (docked or floating, kept per browser in `localStorage`; rules in `shell/panels.ts`), the canvas viewport (pan and zoom; maths in `shell/view.ts`), the editing commands (`shell/commands.ts`) and their keys (`shell/keys.ts`). `canvas/` is the stage (the HMI page and the preview), the layout overlay (`Canvas.tsx`, snapping in `snap.ts`, distributing in `arrange.ts`) and `canvas.css`, the one stylesheet. Everything else is Tailwind v4 with shadcn on Base UI (`components/ui/`, added with `npx shadcn add` in `designer/`), plus the Designer's own small pieces in `components/designer/`. `panels/screens/` is the left panel. `panels/inspector/` is the right panel: the Design tab (`Arrange`, `Properties`, `Settings` for the screen and screen file) and the Prototype tab (`Prototype.tsx`: action and link, focus order, navigation view). Words on screen follow `GLOSSARY.md` (Screen, Element, Widget; Theme is the kit's, Appearance the Designer's). Storybook (`npm run storybook`, `npm run build-storybook`; config in `designer/.storybook/`) is for developing panels: stories sit beside their panel, and the decorator makes a store per story from `parameters.screenFile` (fixtures in `designer/src/fixtures/screen-files.ts`) with `parameters.editor` for further setup. It is not part of `npm test`. `starter/`: the starter app (README there): `main.js` the example entry, `app/` the package tree (`screens.json`, `images/`, the rest written by `tools/gen_package.js`), `lib/` copies of `runtime/` and `kit/` that `starter/tools/build.js` refreshes (a test keeps them equal: rebuild and commit after changing either), `vendor/` mgu-store's render client, packer and linker, pinned and synced with the kit by `scripts/sync-kit.js`. `node starter/tools/build.js [--sdk <donor>]` packs it; tests link it against a made-up donor (`test/fixtures/synthetic-donor.js`) and, with `NODE8`, run the linked bundle under Node 8.
- `test/*.test.js`: all tests, run with `npm test` (`node --test`). Tests that load the runtime require `test/flat-layout.js` first, so the runtime's basename requires of kit modules (`./i18n.js`) resolve to `kit/` as in the flat app layout. `test/fixtures/mgu-store/` holds Store files synced with the kit; `test/golden/` holds golden recordings (refresh with `UPDATE_GOLDEN=1 npm test` after a deliberate sync).
- `test/designer-preview-golden.test.js` builds the Designer and drives it in Playwright's Chromium (`require('playwright')`; skipped without it), requiring every preview frame to equal Node's recording of the same screen.
- The browser tests (`test/designer-*.test.js`) each build the Designer into a folder of their own (`test/designer-dist.js`; files run at the same time), and find things only by `data-*` hooks and ARIA roles, never class names, so restyling can't break them. Keep the hooks when rebuilding a component. Controls the tests drive natively (the link field's `<select>`, the toolbar's Open `<input type=file>`, kept outside the menu) stay native.
- `NODE8=<node 8 binary> npm test` also runs the runtime under Node 8 (`npm pack node-linux-x64@8.16.2` gives one); skipped without.
- The sync test needs a local mgu-store clone (`MGU_STORE`, default `../mgu-store`) and is skipped without one.
